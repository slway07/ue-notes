Behavior Tree ③ — Task와 Latent

Task는 ExecuteTask 로 시작해 Succeeded · Failed · InProgress · Aborted 중 하나를 돌려준다. InProgress 가 Latent Task 이고, 나중에 FinishLatentTask 로 끝낸다.

1. Task의 생애

UBTTaskNode::ExecuteTask(OwnerComp, NodeMemory)
  ├── Succeeded  → 부모 Composite에 성공 통보
  ├── Failed     → 실패 통보
  ├── Aborted    → 중단됨
  └── InProgress → Latent. 나중에 FinishLatentTask/FinishLatentAbort

즉시 끝나는 Task는 Succeeded/Failed 를 바로 돌려준다. 이동·대기·몽타주처럼 시간이 걸리는 Task는 InProgress 를 돌려주고, 완료되면 FinishLatentTask(OwnerComp, Result) 를 호출한다.

중단될 때는 AbortTask 가 불리고, Task는 FinishLatentAbort 로 중단을 완료한다. 이때 OnTaskFinished(..., EBTNodeResult::Aborted) 가 통지된다. 이때 이동 취소·타이머 해제·몽타주 정지 를 빼먹으면 "중단했는데 계속 움직인다"가 된다.

4. Latent Task의 완료와 중단

  • 정상 완료 — ExecuteTask → InProgress → 이동 완료 → FinishLatentTask(Succeeded) → 부모가 다음 자식으로.
  • 중단 — Decorator Observer/StopTree → AbortTask → FinishLatentAbort → OnTaskFinished(..., Aborted) → 부모가 Aborted 처리.

FinishLatentTask 를 호출하지 않으면 BT는 그 Task에서 영원히 멈춘다. 반대로 이미 끝난 Task에 또 호출하면 경고가 난다. 완료를 한 번만 보장하는 게 Latent Task의 핵심이다.

5. AI Task와 GameplayTask

MoveTo·EQS 같은 복잡한 Task는 UAITask (UAITask_MoveTo, UAITask_RunEQS)를 사용한다. AI Task는 GameplayTask 기반이라 취소·재시작·소유권 을 엔진이 관리한다.

  • UBTTask_GameplayTaskBase — GameplayTask를 감싸는 BT Task 기반.
  • UAITask_MoveTo — MoveTo 요청을 AI Task로 감싼 것.
  • UAITask_RunEQS — EQS를 AI Task로 감싼 것.

직접 Task를 만들 때 MoveTo를 매번 새로 짜기보다 UAITask_MoveTo 를 쓰는 편이 중단/재시작 처리가 안전하다.

6. 노드 메모리와 인스턴싱

Task의 상태는 두 곳에 둘 수 있다.

  • NodeMemory — BT 컴포넌트가 인스턴스마다 할당하는 바이트 배열. GetInstanceMemorySize 로 크기를 정한다. MoveTo는 FBTMoveToTaskMemory 에 AI Task 핸들을 둔다.
  • bCreateNodeInstance — 노드 오브젝트 자체를 인스턴스별로 만든다. 멤버 변수에 상태를 둘 수 있지만, 인스턴스 수만큼 오브젝트가 생긴다.

여러 AI가 같은 BT 에셋을 공유하므로, 에셋 노드의 멤버에 상태를 두면 모든 AI가 상태를 공유 한다. 상태는 반드시 NodeMemory나 인스턴스 노드에 둔다.

7. 커스텀 Task의 뼈대

EBTNodeResult::Type UMyTask::ExecuteTask(
    UBehaviorTreeComponent& OwnerComp, uint8* NodeMemory)
{
    // 1. Blackboard에서 대상 읽기
    // 2. 작업 시작
    // 3. 즉시 끝나면 Succeeded/Failed
    // 4. 시간이 걸리면 InProgress
    return EBTNodeResult::InProgress;
}

void UMyTask::OnTaskFinished(...) { /* 정리 */ }

Latent로 시작했다면 완료 시 FinishLatentTask, 중단 시 FinishLatentAbort 를 반드시 호출한다. 타이머·델리게이트·AI Task를 걸었다면 OnTaskFinished(..., Aborted) 에서 해제한다.

8. 디버깅

  • Gameplay Debugger — ActiveNodes에서 어떤 Task가 InProgress 인지.
  • BT 에디터 PIE — 실행 중 Task 하이라이트.
  • 이동이 안 끝나면 FinishLatentTask 가 불리는지, PathFollowing 결과가 Invalid/Blocked 인지 본다.
  • stat AIBehaviorTree — Task/트리 평가 비용.
