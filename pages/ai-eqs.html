EQS — 어디로 갈까

Environment Query System. Generator 가 후보 지점을 만들고, Test 가 점수를 매기거나 걸러 낸다. "숨을 곳", "공격할 자리", "배회할 지점"을 공간 질의로 고른다.

AI Controller Blackboard BT 구조 BT 노드 BT Task Perception EQS

1. EQS의 세 단계

Generator  →  Test  →  결과
후보 생성      점수/필터    SingleResult / AllMatching

EQS는 "어떤 지점이 좋은가"를 한 번에 계산한다. BT의 RunEQSQuery Task가 대표적이고, 블루프린트에서 RunEQSQuery 함수로 직접 호출할 수도 있다.

2. EnvQuery 에셋

구성역할
UEnvQuery쿼리 에셋. Option 목록
UEnvQueryOptionGenerator + Test 목록 한 묶음
UEnvQueryGenerator후보 지점/액터 생성
UEnvQueryTest후보 점수/필터
UEnvQueryContextGenerator/Test에 넘길 기준 위치/액터

Option이 여러 개면 각각 독립적으로 후보를 만들고, 가장 좋은 결과를 고른다. 보통은 Option 하나에 Generator 하나 + Test 여러 개를 둔다.

3. Generator — 후보 만들기

Generator만드는 후보
SimpleGrid중심 주변 격자 점
Donut도넛 모양 링 위의 점
OnCircle원 위의 점
ActorsOfClass특정 클래스 액터들
CurrentLocation현재 위치 하나
PerceivedActorsPerception이 감지한 액터들
Composite여러 Generator를 합침

SimpleGrid는 GridSize, SpaceBetween, GenerateAround 로 격자를 만든다. 격자 크기 × 간격이 후보 수를 결정하므로, EQS 비용의 첫 번째 변수다.

4. Test — 점수와 필터

Test보는 것
Distance기준 컨텍스트와의 거리
Dot방향(정면/후면) 일치도
Trace시야/LOS 차단
Overlap특정 볼륨/액터와 겹침
Pathfinding경로 존재/길이
ProjectNavMesh 위로 투영
Random무작위 점수
Volume볼륨 안/밖

각 Test는 TestPurpose 를 갖는다.

  • Filter — 조건을 못 넘으면 후보를 버린다.
  • Score — 점수만 매긴다.
  • FilterAndScore — 둘 다.

ScoringFactor 는 점수 가중치, ClampMin/ClampMax 는 점수 범위, FilterType 은 최소/최대/범위/일치 조건을 정한다. "거리는 가깝게, 시야는 트여 있게"를 동시에 원하면 Test 두 개를 넣고 가중치를 조절한다.

그림은 SimpleGrid + Distance Test 하나의 개념도다. 실제 EQS는 여러 Test의 점수를 합산하고, Filter Test는 후보를 아예 제거한다.

5. Context — 기준은 누구인가

Generator와 Test는 "무엇을 기준으로" 계산할지 Context를 받는다.

Context의미
EnvQueryContext_Querier쿼리를 요청한 AI 자신
EnvQueryContext_Item현재 평가 중인 후보
EnvQueryContext_NavigationDataNavData
EnvQueryContext_BlueprintBase블루프린트 커스텀 컨텍스트

"플레이어와의 거리"를 보고 싶다면 Distance Test의 Context를 플레이어로 바꾼다. 커스텀 Context는 블루프린트에서 위치/액터 배열을 돌려주도록 만든다.

6. 실행 — RunQuery

FEnvQueryRequest Request(QueryTemplate, Querier);

UEnvQueryManager::RunQuery(Request, EEnvQueryRunMode::SingleResult, FinishDelegate);
// 또는 Request.Execute(EEnvQueryRunMode::SingleResult, FinishDelegate);

UEnvQueryManager::RunQuery 는 쿼리 인스턴스를 만들고, 완료 델리게이트로 결과를 준다. 블루프린트에서는 UEnvQueryManager::RunEQSQuery 가 UEnvQueryInstanceBlueprintWrapper 를 돌려준다.

RunMode결과
SingleResult가장 좋은 하나
RandomBest5Pct상위 5% 중 무작위
RandomBest25Pct상위 25% 중 무작위
AllMatching조건을 통과한 전부

UEnvQueryInstanceBlueprintWrapper 는 GetResultsAsActors·GetResultsAsLocations 로 결과를 꺼내고, OnQueryFinishedEvent 로 완료를 받는다.

7. BT에서 — RunEQSQuery

UBTTask_RunEQSQuery 는 EQSRequest(FEQSParametrizedQueryExecutionRequest)를 받아 EQS를 실행하고, 결과를 Blackboard 키에 넣는다. UBTService_RunEQS 는 가지가 살아 있는 동안 주기적으로 실행한다.

  • Task는 "한 번" 질의하고 결과로 행동을 시작.
  • Service는 "주기적으로" 갱신. 매 틱이 아니다.
  • 결과 키는 Object 또는 Vector 타입이어야 한다.

8. 성능 — EQS는 비싸다

EQS는 후보 수 × Test 수만큼 계산한다. SimpleGrid 20×20 = 400 후보에 Test 4개면 1,600번 평가다. 매 틱 돌리면 AI 수만큼 곱해진다.

  • 격자 크기/간격을 줄여 후보 수를 줄인다.
  • Service는 Interval 을 크게, Task는 정말 필요할 때만.
  • Pathfinding Test는 특히 비싸다. 모든 후보에 경로를 묻지 않는다.
  • 멀리 있는 AI는 EQS를 덜 돌린다(중요도/거리 티어링).

9. 디버깅

  • Gameplay Debugger (') — EQS 카테고리에서 후보 점수/필터 결과를 본다.
  • EQS Testing Pawn — 에디터에서 쿼리를 직접 돌려 후보를 시각화.
  • 결과가 비면 Generator 후보 0개인지, Filter Test가 전부 버렸는지부터 확인한다.
