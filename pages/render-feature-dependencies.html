Lumen · Nanite · VSM — 무엇이 무엇 없이 돌아가나

UE5 에서 같이 소개된 기능들이라 한 묶음처럼 보이지만 대부분 서로 독립적이다. 딱 한 군데만 진짜 의존이 있다.

1. 왜 헷갈리는가

Lumen, Nanite, Virtual Shadow Maps, TSR, World Partition, HLOD. 이 여섯은 UE5 소개 자료에 늘 함께 나온다. 그래서 하나를 끄면 다른 것도 못 쓰는 것 아닌가 하는 인상을 받기 쉽다.

실제로는 대부분 서로를 모른다. 코드를 열어 보면 include 조차 하지 않는 조합이 많다. 다만 딱 한 쌍에 진짜 의존이 있고, 그것이 가장 자주 오해되는 쌍이기도 하다.

2. 의존 지도

그림 읽는 법

동그라미 여섯 개가 각 기능이다. 누르면 그 기능을 껐다 켰다 할 수 있다. 선이 있으면 의존 관계가 있다는 뜻이고, 두 종류다.

그림의 요소무엇인가
굵은 실선필수 의존. 가리키는 쪽이 꺼지면 이쪽도 같이 꺼진다
가는 점선선택적 활용. 있으면 더 빠르거나 품질이 좋아지지만, 없어도 다른 경로로 동작한다
흐려진 동그라미꺼진 기능. 직접 껐거나, 의존하던 것이 꺼져서 끌려 내려간 것

해 볼 것. Nanite 를 눌러 꺼 보라. Virtual Shadow Maps 가 같이 흐려진다. 이것이 이 그림에서 유일한 연쇄다. 반대로 World Partition 을 꺼 보면 HLOD 만 따라 꺼지고 렌더링 기능 넷(Lumen · VSM · TSR · Nanite)은 아무 영향이 없다 — 렌더링 쪽은 World Partition 을 전혀 모른다.

3. VSM 과 Nanite — 유일한 진짜 의존

가장 많이 오해되는 쌍이다. "Virtual Shadow Maps 는 Nanite 와 상관없다" 는 말도 돌고, "Nanite 가 있어야 쓴다" 는 말도 돈다. 둘 다 반쯤 맞다. 질문을 둘로 나눠야 답이 갈린다.

질문답
VSM 을 쓰려면 메시가 Nanite 여야 하나?아니다
VSM 을 쓰려면 Nanite 기능이 켜져 있어야 하나?그렇다

엔진 코드가 그대로 말해 준다. VSM 사용 여부를 정하는 함수는 조건 세 개를 모두 요구한다.

bool UseVirtualShadowMaps(EShaderPlatform ShaderPlatform)
{
    return bVirtualShadowMapsEnabled                       // r.Shadow.Virtual.Enable
        && DoesPlatformSupportVirtualShadowMaps(ShaderPlatform)
        && DoesRuntimeSupportNanite(ShaderPlatform, true, true);
}

그리고 가운데의 DoesPlatformSupportVirtualShadowMaps 안에 또 Nanite 검사가 들어 있다.

return bIsProjectEnable                 // r.Shadow.Virtual.ProjectEnabled
    && DoesPlatformSupportNanite(Platform);

그래서 r.Nanite.ProjectEnabled 를 0 으로 두면 VSM 은 아예 켜지지 않는다. 프로젝트 설정에서 Nanite 지원을 끄는 것과 같다.

그런데도 "메시가 Nanite 일 필요는 없다" 가 동시에 참인 이유는, 일반 메시를 VSM 에 그려 넣는 경로가 따로 있기 때문이다. r.Shadow.Virtual.NonNanite.ProjectEnabled 로 켜지는 이 경로 덕분에 Nanite 가 아닌 스태틱 메시·스켈레탈 메시도 그림자를 드리운다. VSM 코드에 non-Nanite 전용 설정이 여러 개 있는 것이 그 증거다.

정리. VSM 이 요구하는 것은 Nanite 라는 기능이 플랫폼·프로젝트에서 켜져 있을 것이지, 장면의 메시가 Nanite 일 것이 아니다. "Nanite 를 안 쓰는 프로젝트" 와 "Nanite 지원을 끈 프로젝트" 는 다르다.

4. Lumen 과 Nanite — 선택적 활용

Lumen 은 Nanite 없이 동작한다. Lumen 의 플랫폼 지원을 판정하는 DoesPlatformSupportLumenGI 는 Nanite 를 전혀 검사하지 않는다.

둘이 만나는 곳은 Surface Cache 의 카드 캡처 한 군데다. Lumen 은 장면을 작은 카드들로 찍어 두고 그걸로 간접광을 계산하는데, 이때

  • Nanite 가 아닌 메시는 일반 메시 드로우 커맨드로 카드에 그려진다 (!Proxy->IsNaniteMesh() 인 것들을 모아서 처리)
  • Nanite 메시는 따로 모아 Nanite 래스터 경로로 캡처한다. 이 경로는 UseNanite(...) && bAnyNaniteMeshes 일 때만 돈다

즉 Nanite 는 빠른 길이 하나 더 생기는 것이지 없으면 안 되는 것이 아니다.

5. Nanite 와 World Partition — 서로 모른다

이 둘 사이에는 코드 의존이 양방향 모두 없다. Nanite 렌더러 폴더 전체에서 WorldPartition 이라는 문자열이 한 번도 나오지 않고, World Partition 의 스트리밍 코어에도 Nanite 호출이 없다.

둘이 스치는 곳은 HLOD 쪽뿐이다. HLOD 메시를 미리 데워 둘 때(HLODRuntimeSubsystem) Nanite 가 켜져 있으면 Nanite 리소스도 함께 웜업하고, HLOD 통계에 Nanite 삼각형 수를 적는 정도다. 전부 있으면 하고 없으면 마는 코드다.

Nanite 는 메시 하나를 어떻게 그릴지의 문제이고, World Partition 은 레벨의 어느 조각을 메모리에 올릴지의 문제다. 다루는 층이 다르다.

6. HLOD 는 두 종류다

"HLOD 가 World Partition 에 의존하는가" 라는 질문에 하나로 답할 수 없다. 구현이 둘이기 때문이다.

7. TSR 은 아무것도 요구하지 않는다

TSR 구현 파일은 Nanite·Lumen·VSM 헤더를 하나도 포함하지 않는다. 유일하게 Nanite 를 언급하는 곳은 r.Nanite.Foliage 값을 읽어 얇은 지오메트리 판정의 기본값을 정하는 부분과, 디버그 표시 플래그를 보는 부분뿐이다.

TSR 은 이미 그려진 화면을 받아 해상도를 올리는 단계라서, 그 앞에서 무엇이 어떻게 그려졌는지는 알 필요가 없다.

9. Nanite 를 끄면 메시는 어떻게 그려지나

Nanite 로 만든 스태틱 메시라도 Nanite 가 꺼져 있으면 폴백 메시로 그려진다. 엔진이 프록시를 만들 때 Nanite 사용 가능 여부를 보고, 안 되면 일반 FStaticMeshSceneProxy 를 만든다. 그래서 Nanite 를 끄는 것만으로 메시가 사라지지는 않는다 — 디테일이 줄어들 뿐이다.
