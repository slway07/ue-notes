StateTree ② — Task · Condition · Evaluator

상태는 빈 상자다. 안에 Task 가 들어가 일을 하고, 트리 위쪽의 Evaluator 가 값을 만들고, Condition 이 문을 지키고, Consideration 이 점수를 매긴다. 이 넷은 모두 인스턴스 데이터를 가진 구조체다.

구조와 실행 노드 4종 전이와 선택

1. 네 종류, 붙는 자리가 다르다

노드붙는 곳하는 일
Task상태실제 행동. 상태의 완료를 결정
Evaluator트리 전역매 틱 값을 갱신해 넘긴다
Condition진입 조건 / 전이참·거짓 판정
Consideration상태(유틸리티)0~1 점수로 선택에 참여

Evaluator 가 상태가 아니라 트리 전역이라는 점이 BT 와 크게 다르다. "플레이어까지의 거리", "체력 비율" 같은 공통 데이터를 한 곳에서 만들어 두고, 상태의 태스크들이 바인딩으로 가져다 쓴다.

UStateTree ├─ Evaluators // 전역 ├─ Global Tasks // 전역 └─ Root State ├─ Enter Conditions ├─ Tasks // 상태 진입~이탈 ├─ Transitions → Conditions └─ 자식 상태들

2. Task 의 생명주기

상태 진입   →  EnterState()      // Running / Succeeded / Failed
매 틱      →  Tick()            // bShouldCallTick 일 때만
상태 완료   →  StateCompleted()  // 새 상태를 고르기 직전
상태 이탈   →  ExitState()

EnterState 가 Succeeded 나 Failed 를 돌려주면 상태는 그 자리에서 완료되고, 같은 틱의 전이 단계에서 다음 상태를 고른다. Running 이면 Tick 을 받으며 계속 산다.

5.8 블루프린트에서는 반환값이 없다. Enter/Tick 이벤트는 값을 돌려주지 않고, Finish Task 노드로 끝낸다. 옛 튜토리얼의 "Succeeded 를 리턴한다"는 C++ 이야기이거나 구버전이다.

완료 판정의미
CompletionTasksControl = Any태스크 하나라도 완료되면 상태 완료 (기본)
All완료로 보는 태스크가 전부 끝나야 상태 완료
bConsideredForCompletion이 태스크를 완료 판정에 넣을지. 끄면 백그라운드로 계속 돈다

해 볼 것. Tick 때 복사 를 끄면 Tick 은 계속 불리는데 오른쪽 값이 멈춘다. 태스크는 상태에 들어올 때 복사된 값만 보므로, 실제로 사거리 안에 들어와도 영영 사거리 밖이라고 판정한다. 이제 Tick 받기 까지 끄면 Tick 자체가 없어서 완료도 일어나지 않는다.

3. Task 의 스위치

플래그기본효과
bShouldCallTicktrue매 틱 Tick 을 부를지. 끄면 바인딩 복사도 없다
bShouldCallTickOnlyOnEventsfalse이벤트가 있을 때만 Tick. 폴링을 줄일 때
bShouldCopyBoundPropertiesOnTicktrueTick 직전에 바인딩을 복사할지
bShouldCopyBoundPropertiesOnExitStatetrueExitState 직전에 복사할지
bShouldStateChangeOnReselecttrue유지(Sustained)된 상태에서도 Enter/Exit 를 받을지
bShouldAffectTransitionsfalse전이 처리 때 TriggerTransitions 를 부를지
bConsideredForSchedulingtrue수면/틱 간격 계산에 이 태스크를 넣을지

"Tick 을 끄면 값도 안 온다"가 첫 번째 함정이다. Tick 이 없으면 바인딩 복사 시점도 없으므로, 태스크는 EnterState 때 받은 값에 머문다. 폴링이 필요 없어서 Tick 을 껐는데 판정이 안 되는 경우가 이거다.

4. Evaluator — 값을 만드는 쪽

TreeStart()  →  Tick(dt) × N  →  TreeStop()

Evaluator 는 트리가 시작될 때 한 번, 그 뒤 매 틱 불린다. 상태와 무관하게 도는 것이 핵심이다. "지금 플레이어와의 거리"를 여기서 계산해 두면, 어느 상태의 태스크든 바인딩으로 같은 값을 본다.

  • 출력 바인딩 — Evaluator 의 값을 다른 곳(파라미터·태스크)으로 보낼 수 있다(OutputBindingsBatch).
  • Evaluator 도 InstanceData 를 가진다. 이전 프레임 값을 기억해 변화량을 계산하는 식이다.
  • 비싼 계산(트레이스·경로)을 여기 몰아 두면 상태마다 중복 계산하지 않는다.

5. Condition — 문을 지키는 쪽

조건은 TestCondition() 하나로 참·거짓을 낸다. 여러 개를 넣으면 Operand 로 묶인다.

항목값의미
OperandAnd / Or앞 결과와 AND / OR
EvaluationModeEvaluated정상 평가
ForcedTrue / ForcedFalse평가하지 않고 결과를 고정 (디버깅·임시 비활성)

조건이 붙는 자리에 따라 의미가 다르다.

  • Enter Conditions — 상태를 고를 때 검사한다. 실패하면 그 상태는 선택되지 않고 다음 후보로 넘어간다.
  • Transition Conditions — 전이가 일어날 조건. 통과해야 전이가 발동한다.
  • 상태 변화 알림 — bHasShouldCallStateChangeEvents 를 켜면 조건도 Enter/Exit/Completed 를 받는다. 조건이 캐시를 들고 있을 때 쓴다.

조건의 인스턴스 데이터는 트리 전체에서 공유된다. 같은 조건 노드를 여러 곳에 써도 인스턴스가 하나라는 뜻이라, TestCondition 안에서 값을 바꾸면 안 된다.

6. Consideration — 점수를 매기는 쪽

Consideration 은 GetScore() 로 0~1 점수를 낸다. 엔진은 GetNormalizedScore() 에서 0~1 로 clamp 만 한다. 여러 개를 넣으면 Operand 가 Min / Max / 곱으로 작동한다.

And      → Min(a, b)     // 둘 다 만족해야 높다
Or       → Max(a, b)     // 하나만 좋아도 높다
Multiply → a * b         // 곱해진다

여기에 상태의 Weight 가 곱해져 최종 점수가 된다. 이 점수를 누가 어떻게 쓰는지는 ③ 전이와 선택 에서 다룬다.

7. InstanceData — 상태는 어디에 남나

모든 노드는 FInstanceDataType 을 선언할 수 있다. 에셋에는 기본값(템플릿) 만 있고, 실행할 때 인스턴스별로 복사본이 만들어진다.

저장소누가 쓰나수명
DefaultInstanceData에셋의 템플릿영구. 실행할 때 복사된다
SharedInstanceDataCondition · Consideration트리 하나에 하나. 여러 곳이 공유
인스턴스 데이터Task · Evaluator상태가 활성인 동안. 재진입하면 새로 만들어진다
ExecutionRuntimeData노드가 원할 때Start~Stop 동안 유지. 상태를 떠나도 남는다

"재진입하면 새로 만들어진다"가 중요하다. 상태를 떠났다가 다시 들어오면 태스크의 인스턴스 데이터는 템플릿에서 다시 복사된다. 이전 값을 기억해야 한다면 ExecutionRuntimeData 나 트리 파라미터에 둔다.

8. 바인딩 — 참조가 아니라 복사

StateTree 의 바인딩은 포인터가 아니다. 정해진 시점에 값을 복사해 온다. 복사 시점은 세 곳이다.

① EnterState 직전 // 항상 ② Tick 직전 // ...OnTick 플래그 ③ ExitState 직전 // ...OnExitState 플래그

출발점이 될 수 있는 것들은 다음과 같다.

소스예
Context스키마가 보장하는 Actor, AIController
Parameter · StateParameter트리 파라미터, 상태 파라미터
Evaluator · GlobalTask평가자가 만든 값
Task · Condition · Consideration같은 상태의 다른 노드 인스턴스 데이터
TransitionEvent · StateEvent전이/선택을 일으킨 이벤트의 payload
PropertyFunction바인딩 안에서 계산하는 함수

그래서 "태스크가 최신 값을 본다"는 보장은 복사 시점이 언제냐에 달려 있다. 위 시뮬레이션에서 복사를 끄면 값이 멈추는 이유다.

9. 파라미터 — 인스턴스마다 다른 값

트리 파라미터는 FInstancedPropertyBag 다. 같은 에셋을 여러 AI 가 공유해도, 컴포넌트의 StateTreeRef 에서 파라미터 기본값만 바꿔 서로 다르게 돌릴 수 있다.

  • 트리 파라미터 — 트리 전체에서 보인다. Evaluator 출력을 여기로 받아 두면 다른 상태가 읽기 쉽다.
  • 상태 파라미터 — 그 상태 안에서만. ParameterBindingsBatch 로 진입 시 채워진다.
  • 파라미터도 바인딩 대상이라, "상태별로 다른 사거리"를 에셋 수정 없이 줄 수 있다.

10. 블루프린트와 C++

종류블루프린트 기반 클래스C++ 기반 구조체
TaskUStateTreeTaskBlueprintBaseFStateTreeTaskBase
EvaluatorUStateTreeEvaluatorBlueprintBaseFStateTreeEvaluatorBase
ConditionUStateTreeConditionBlueprintBaseFStateTreeConditionBase
ConsiderationUStateTreeConsiderationBlueprintBaseFStateTreeConsiderationBase

블루프린트 노드는 UObject 이고, C++ 노드는 구조체다. BP 쪽은 GetOwnerActor()·GetWorld() 를 그대로 쓸 수 있어 편하지만, 노드마다 오브젝트가 생기므로 수가 많아지면 비용이 된다. 반복이 잦은 판정은 C++ 구조체가 가볍다.
