AnimBP는 한 프레임에 무엇을 하나

Update는 게임 스레드와 워커 스레드로 갈린다. 어느 쪽에서 도는지를 알면 스레드 세이프 규칙이 암기가 아니게 된다.

AnimBP 를 열면 그래프가 두 개다. 이벤트 그래프는 값을 계산하고, 애님 그래프는 포즈를 계산한다. 둘은 같은 프레임 안에서 다른 시점에, 때로는 다른 스레드에서 돈다. 이 순서를 모르면 "왜 여기선 되고 저기선 안 되나"가 전부 외울 거리가 된다.

1. 한 프레임의 순서

그림의 박스를 누르면 그 단계가 무슨 일을 하는지 아래에 나온다. 토글로 병렬이 켜진 경우와 꺼진 경우를 오갈 수 있다. 위 레인이 게임 스레드, 아래 레인이 워커 스레드다.

레인 사이를 잇는 비스듬한 선은 스레드가 바뀌는 지점이다. 병렬을 끄면 4~7번이 전부 게임 스레드 레인으로 올라가고 워커 레인은 비게 된다. 좁은 화면에서는 같은 내용이 세로로 바뀌어, 시간이 위에서 아래로 흐르고 좌우 두 칸이 스레드가 된다.

그림의 "워커 스레드" 한 줄은 스레드 한 개가 아니다

워커 스레드는 여러 개다. Windows 에서는 하이퍼스레딩이 있으면 논리 프로세서 수 - 2, 없으면 물리 코어 수 - 1 개를 띄우고, 최소 2 개는 보장한다. 4 개로 묶는 상한은 데디케이티드 서버에만 걸린다.

그런데 더 중요한 것은 작업을 쪼개는 단위다. 병렬 애니메이션 작업 하나(FParallelAnimationEvaluationTask)가 들고 있는 것은 스켈레탈 메시 컴포넌트 한 개이고, 그 작업을 던지는 쪽도 컴포넌트 자신의 틱에서 한 번 던진다. 즉 캐릭터 한 마리 = 작업 한 개 = 워커 한 개이고, 그 캐릭터의 계산은 시작부터 끝까지 같은 워커에서 돈다.

그래서 병렬은 캐릭터 사이에서 생기고, 캐릭터 안에서는 생기지 않는다. 애님 그래프의 노드들이 서로 다른 코어로 나뉘어 도는 것이 아니라, 한 작업 안에서 순차로 돈다.

  • 캐릭터 한 마리의 AnimBP 가 무거우면 코어를 늘려도 그 한 마리는 빨라지지 않는다. LOD, 업데이트 빈도 조절(Update Rate Optimization), 노드 수 줄이기로 풀어야 한다
  • 캐릭터 수가 많을 때는 코어를 늘린 만큼 이득이 있다. 동시에 처리되는 캐릭터 수가 늘기 때문이다
  • 위 그림의 아래 레인은 "스레드 한 개"가 아니라 "이 캐릭터 한 마리의 작업이 올라가는 자리" 로 읽어야 한다

2. 세 개의 Update 는 무엇이 다른가

이름이 비슷한 Update 가 셋이다. 어느 스레드에서 도는지가 액터 접근 가능 여부를 정한다.

노드 / 함수스레드액터·컴포넌트 직접 접근쓰임
Event Blueprint Update Animation게임가능간단한 값 읽기. 단 병렬화가 막히는 원인이 되기도 한다
Blueprint Thread Safe Update Animation워커금지무거운 계산을 여기로 옮긴다
애님 그래프 Update워커금지전이 판정, 시간 전진

워커 스레드 단계에서 액터나 컴포넌트를 직접 읽으면 게임 스레드가 같은 값을 쓰고 있을 수 있다. 같은 데이터를 한쪽이 읽는 동안 다른 쪽이 고치면 결과가 무엇이 될지 정해지지 않는다. 그래서 금지다.

그 대신 게임 스레드 단계에서 필요한 값을 미리 변수에 복사해 두고, 워커 단계에서는 그 변수만 쓴다. 엔진이 이 복사를 자동으로 해 주는 장치가 Property Access 다.

엔진 헤더의 NativeUpdateAnimation 주석도 같은 말을 한다. 이 단계에서는 값을 모으기만 하고, 무거운 일은 스레드 세이프 쪽에서 하라는 취지다.

3. 병렬이 안 될 때

다음 중 하나라도 해당하면 병렬로 넘어가지 않는다. NeedsImmediateUpdate() 가 true 를 돌려주고, 그 프레임은 전부 게임 스레드에서 즉시 처리된다.

  • 엔진 설정 bAllowMultiThreadedAnimationUpdate 가 꺼져 있다
  • 이 AnimBP 의 bUseMultiThreadedAnimationUpdate 가 꺼져 있다
  • DeltaSeconds 가 0 이다 (일시정지 등)
  • 콘솔 변수 a.ParallelAnimUpdate 또는 a.ParallelAnimEvaluation 이 0 이다
  • 루트 모션 모드가 RootMotionFromEverything 이고 유효한 루트 모션이 필요하다
  • 에디터에서 이 AnimBP 를 디버깅 중이거나 브레이크포인트가 걸려 있다

a.ParallelAnimEvaluation 의 기본값은 1 이다. 0 이면 평가를 전부 게임 스레드에서 한다. a.ParallelAnimUpdate 는 업데이트 쪽에서 같은 역할을 한다.

특히 에디터에서 AnimBP 를 디버깅하면 자동으로 게임 스레드로 내려온다. 그래서 "에디터에서는 멀쩡한데 빌드에서만 문제가 생긴다"가 가능하다. 반대로 에디터에서만 느린 것도 설명이 된다. 이것이 스레드 세이프 규칙을 어겨도 에디터에서는 한동안 들키지 않는 이유다. 디버깅 대상은 게임 스레드에서 돌려야 워치와 브레이크포인트가 동작하기 때문이다.

4. Evaluate 는 따로다

Update 는 "어떤 애니메이션을 얼마나 틀지" 를 정하고, Evaluate 는 "그래서 뼈가 어디에 놓이는지" 를 계산한다.

둘은 다른 단계다. Update 에서 정한 값이 그 프레임의 Evaluate 에 쓰인다.

Event Blueprint Post Evaluate Animation 은 포즈가 다 나온 뒤 게임 스레드에서 돈다. 계산된 뼈 위치를 읽어야 할 때 쓰는 자리다.
