CharacterMovement — 네트워크 예측과 보정

클라이언트는 먼저 움직이고, 서버가 같은 입력으로 다시 움직여 검사한다. 오차가 크면 클라이언트를 되감고, 남은 입력을 다시 재생한다.

개요 캐릭터 물리 네트워크 Root Motion 그 외

1. 예측과 권한 — 둘 다 필요하다

캐릭터 이동은 서버 권한이지만, 입력마다 서버 응답을 기다리면 조작감이 무너진다. 그래서 UCharacterMovementComponent 는 클라이언트 예측(client prediction) 을 한다. 클라이언트가 먼저 움직이고, 서버가 나중에 같은 입력을 재시뮬레이션해서 검사한다.

이를 위해 UCharacterMovementComponent 는 INetworkPredictionInterface 를 구현한다. 핵심은 세 가지다.

  • 클라이언트 — 입력을 FSavedMove_Character 로 저장하고, 로컬에서 먼저 PerformMovement 한다.
  • 서버 — 같은 입력을 MoveAutonomous 로 재시뮬레이션하고, 클라이언트 위치와 비교한다.
  • 보정 — 오차가 크면 서버가 ClientAdjustPosition 을 보내고, 클라이언트는 저장해 둔 이동을 다시 재생한다.

권한 분기는 ControlledCharacterMove() 한 곳에서 갈린다.

if (CharacterOwner->GetLocalRole() == ROLE_Authority)
    PerformMovement(DeltaSeconds);                 // 서버
else if (GetLocalRole() == ROLE_AutonomousProxy && IsNetMode(NM_Client))
    ReplicateMoveToServer(DeltaSeconds, Acceleration); // 조종 중인 클라이언트

2. 클라이언트 — 예측하고 저장한다

클라이언트의 중심은 ReplicateMoveToServer 다. 매 틱(또는 전송 간격마다) 이 함수가 돈다.

  1. 시간 갱신 — FNetworkPredictionData_Client_Character::UpdateTimeStampAndDeltaTime 으로 타임스탬프와 delta를 맞춘다.
  2. SavedMove 생성 — CreateSavedMove 로 FSavedMove_Character 를 하나 얻고, SetMoveFor 로 이번 입력·시작 위치·속도·상태를 기록한다.
  3. 이전 move와 합치기 — PendingMove 가 있고 CanCombineWith 가 true면 하나로 합친다. 전송량을 줄이는 최적화다.
  4. 로컬 이동 — PerformMovement(NewMove->DeltaTime) 으로 클라이언트가 먼저 움직인다.
  5. 저장 — SavedMoves 에 넣는다. 아직 서버가 확인하지 않은 이동 목록이다.
  6. 전송 — CallServerMove 또는 packed RPC로 서버에 보낸다.

SavedMoves 에 넣고 전송하는 일은 IsReplicatingMovement()(bReplicateMovement)가 true일 때만 일어난다. 전송은 매 틱이 아니라 GetClientNetSendDeltaTime() 간격(1/120~1/5초)으로 조절되고, 그 사이 move는 PendingMove 로 합쳐진다.

FSavedMove_Character 는 단순한 입력 로그가 아니다. 시작/끝 위치, 속도, 가속도, 이동 모드, 발판, 점프 플래그, 루트 모션까지 들어 있다. 서버가 같은 결과를 재현하려면 이 정보가 필요하다.

// 개념적인 저장 항목
StartLocation, StartRotation, Velocity, Acceleration
MovementMode, CustomMovementMode
StartBase, EndBase, StartBoneName, EndBoneName
CompressedFlags   // 점프·웅크리기 등
RootMotion        // 애니메이션 루트 모션

압축 플래그는 1바이트에 상태를 담는다. 기본 구현은 점프·웅크리기만 세팅하고, FLAG_Custom_0..3 은 서브클래스가 쓴다.

플래그비트의미
FLAG_JumpPressed0x01점프 입력
FLAG_WantsToCrouch0x02웅크리기 의도
FLAG_Custom_0..30x10~0x80게임이 정의한 상태

CanCombineWith() 는 아무 move나 합치지 않는다. bForceNoCombine, 루트 모션, 가속도 방향 차이, MaxSpeed 변화, 점프 상태 변화, 압축 플래그 불일치, 발판·이동 모드·캡슐 크기 변화가 있으면 합치지 않는다. 합치면 서버가 재현할 수 없는 move가 되기 때문이다.

prediction data는 move를 최대 96개까지 보관한다(MaxSavedMoveCount·MaxFreeMoveCount). AckMove() 가 서버가 확인한 move까지 풀에 돌려주고, SavedMoves 에서 제거한다.

전송은 ServerMove RPC다. 최근 엔진은 FCharacterNetworkMoveDataContainer 로 묶어 packed RPC 를 쓰는 경로가 기본이다. 구형 경로(CallServerMove)도 남아 있지만, 확장은 보통 네트워크 move data 쪽에서 한다.

3. 서버 — 같은 입력으로 다시 움직인다

이동 RPC는 컴포넌트가 아니라 ACharacter 에 있다. 컴포넌트 RPC의 오버헤드를 피하려고 ServerMovePacked·ClientMoveResponsePacked 를 액터에 두고, 실제 처리는 CharacterMovement로 위임한다.

packed 경로는 이렇게 흐른다.

  1. ServerMovePacked_ServerReceive — 비트스트림을 풀기 전에는 검증할 수 없어 Validate 는 true를 반환한다. 실제 거부는 비트 수 상한(NetPackedMovementMaxBits)과 타임스탬프로 한다.
  2. ServerMove_HandleMoveData — OldMove(재전송) → PendingMove(듀얼) → NewMove 순서로 ServerMove_PerformMovement 를 호출한다. 오차 검사는 NewMove에서만 한다.
  3. ServerMove_PerformMovement — VerifyClientTimeStamp 실패 시 return, GetServerMoveDeltaTime 으로 delta를 구한 뒤 MoveAutonomous 를 호출한다.
// UCharacterMovementComponent::MoveAutonomous
UpdateFromCompressedFlags(CompressedFlags);
CharacterOwner->CheckJumpInput(DeltaTime);

Acceleration = ConstrainInputAcceleration(NewAccel);
Acceleration = Acceleration.GetClampedToMaxSize(GetMaxAcceleration());
PerformMovement(DeltaTime);

즉 서버도 클라이언트와 같은 PerformMovement 를 돈다. 같은 입력, 같은 delta, 같은 시작 상태라면 같은 결과가 나와야 한다. 이 전제가 깨지는 것이 네트워크 이동 문제의 대부분이다.

이동이 끝나면 ServerMoveHandleClientError 가 클라이언트가 보고한 위치와 서버 위치를 비교한다. ServerCheckClientError 는 bIgnoreClientMovementErrorChecksAndCorrection 이면 검사를 생략하고, 아니면 이동 모드 불일치 또는 AGameNetworkManager::ExceedsAllowablePositionError 로 판정한다. 테스트용 p.NetForceClientAdjustmentPercent 로 보정을 강제할 수도 있다.

오차가 크면 bNetworkLargeClientCorrection 이 켜져 우선순위가 올라가고, GetTeleportType() 도 이를 TeleportPhysics 로 취급한다. 보정은 그 자리에서 바로 보내지 않고 프레임 끝 SendClientAdjustment() 에서 스로틀한다. ack는 NetworkMinTimeBetweenClientAckGoodMoves, 보정은 NetworkMinTimeBetweenClientAdjustments(대형 보정은 별도 간격)로 간격을 둔다.

서버가 클라이언트를 믿는 예외 — bServerAcceptClientAuthoritativePosition 또는 AGameNetworkManager::ClientAuthorativePosition 이 켜져 있으면 서버가 클라이언트 위치를 그대로 받아들인다. 기본은 꺼져 있다.

4. 보정 — 되감고 다시 재생한다

서버가 보내는 ClientAdjustPosition 에는 서버가 계산한 위치·속도·회전·이동 모드·발판이 들어 있다. 클라이언트는 이 값을 그대로 적용하고, 아직 확인되지 않은 이동을 다시 재생한다.

#클라이언트서버
1입력
2PerformMovement — 예측 이동
3ServerMovePacked 전송
4MoveAutonomous — 재시뮬레이션
5ServerCheckClientError — 오차 검사
6ClientAdjustPosition 수신오차가 크면 전송
7SavedMoves를 MoveAutonomous 로 재생

수신은 MoveResponsePacked_ClientReceive → 응답 컨테이너 Serialize → ClientHandleMoveResponse 로 이어진다. 여기서 ack면 ClientAckGoodMove_Implementation, 보정이면 루트 모션 소스 → 루트 모션 몽타주 → 일반 ClientAdjustPosition_Implementation 순으로 분기한다.

ClientAdjustPosition_Implementation 은 먼저 bClientIgnoreMovementCorrections 를 확인한다. 켜져 있으면 ack만 하고 위치는 건드리지 않는다. 그다음 타임스탬프로 SavedMoves 에서 move를 찾고, 없으면(이미 ack된 과거) 그냥 끝낸다. 있으면 AckMove 후 서버 위치를 SetWorldLocation(..., TeleportPhysics) 로 적용하고, 속도·이동 모드·발판을 맞춘 뒤 UpdateFloorFromAdjustment·bJustTeleported = true·bUpdatePosition = true 로 끝낸다.

재생은 그 자리에서 하지 않는다. 다음 TickComponent 가 bUpdatePosition 을 보고 ClientUpdatePositionAfterServerUpdate 를 호출한다. 이때 남은 SavedMoves 를 하나씩 PrepMoveFor → MoveAutonomous → PostUpdate(PostUpdate_Replay) 로 다시 실행한다. PerformMovement 만 부르는 게 아니라 서버와 같은 MoveAutonomous 경로를 쓴다는 점이 중요하다.

재생 동안 CharacterOwner->bClientUpdating 이 켜진다. 이 플래그는 DoJump·ShouldNotifyLanded·TickCharacterPose 가 "재생 중"을 구분하게 해서, 루트 모션·애니메이션 이벤트·노티파이가 두 번 발생하지 않게 막는다. 재생은 "이미 일어난 일을 다시 계산"하는 것이지, 새 입력을 처리하는 것이 아니다.

ClientVeryShortAdjustPosition 은 속도가 0일 때 대역폭을 아끼는 legacy 버전이다. packed 응답 경로에서는 ClientHandleMoveResponse 가 항상 ClientAdjustPosition_Implementation 을 부르므로, 이 짧은 버전은 legacy RPC에서만 쓰인다.

보정이 오면 화면이 순간이동할 수 있다. 그래서 네트워크 스무딩이 그 차이를 시각적으로 메운다.

5. 스무딩 — 보정을 부드럽게

NetworkSmoothingMode 는 원격 캐릭터(시뮬레이티드 프록시)의 위치 보간 방식을 정한다. 기본은 Exponential 이다.

모드동작
Disabled네트워크 갱신을 그대로 적용. 순간이동이 보인다
Linear이전 위치에서 목표 위치로 선형 보간
Exponential목표에 가까울수록 느려지는 지수 보간. 기본

스무딩은 네트워크 갱신이 올 때 시작된다. SmoothCorrection() 이 이전 위치와 새 위치의 차이를 MeshTranslationOffset 에 쌓고, 캡슐은 새 위치로 옮기되 메시는 그 자리에 붙잡아 둔다(FScopedPreventAttachedComponentMove). 그다음 SmoothClientPosition 이 매 틱 오프셋을 줄여 메시를 따라오게 한다.

  • Linear — 이전 위치에서 목표까지 선형 보간. SmoothingClientTimeStamp 를 서버 쪽으로 밀며 LerpPercent 를 계산한다.
  • Exponential — MeshTranslationOffset 을 (1 - DeltaSeconds / SmoothLocationTime) 로 지수 감쇠. 목표에 가까울수록 느려진다.
  • Disabled — 오프셋 없이 즉시 스냅.

너무 멀리 떨어진 보정은 스무딩하지 않는다. NetworkMaxSmoothUpdateDistance 를 넘으면 오프셋을 방향별 최대치로 자르고, NetworkNoSmoothUpdateDistance 를 넘으면 오프셋을 0으로 만들어 사실상 순간이동시킨다.

관련 값은 NetworkSimulatedSmoothLocationTime(기본 0.1초), NetworkSimulatedSmoothRotationTime(0.05초)이다. 리슨 서버에서는 ListenServerNetworkSimulatedSmooth*(0.04·0.033초)를 따로 쓴다.

스무딩은 시각적 보정이다. 실제 충돌·판정은 서버가 본 위치를 기준으로 하므로, 화면에서 부드럽게 보여도 판정은 다를 수 있다.

시뮬레이티드 프록시는 조종하지 않는 원격 캐릭터다. TickComponent 의 ROLE_SimulatedProxy 분기에서 SimulatedTick 을 돌리고, ReplicatedMovement·ReplicatedBasedMovement 가 도착하면 PostNetReceiveLocationAndRotation·OnRep_ReplicatedBasedMovement 가 SmoothCorrection 을 호출한다. 캡슐이 복제 반올림 때문에 벽에 끼는 것을 줄이려면 bShrinkProxyCapsule 로 프록시 캡슐을 줄인다.

6. 확장 — 커스텀 이동 데이터

이동 모드를 직접 만들었거나 입력을 더 보내야 한다면, 기본 RPC에 데이터를 얹는다.

  • FSavedMove_Character 파생 — 저장할 필드를 늘리고 SetMoveFor·Clear·CanCombineWith·GetCompressedFlags 를 재정의한다.
  • FNetworkPredictionData_Client_Character 파생 — AllocateNewMove 에서 커스텀 move를 만들고, GetPredictionData_Client 를 재정의한다.
  • FCharacterNetworkMoveData · FCharacterNetworkMoveDataContainer — RPC에 실리는 데이터를 확장한다. GetNetworkMoveDataContainer 를 재정의한다.

FCharacterNetworkMoveData 는 ClientFillNetworkMoveData() 와 Serialize() 가 virtual이다. 파생 컨테이너 생성자에서 NewMoveData·PendingMoveData·OldMoveData 포인터를 자기 구조체로 갈아끼우고, SetNetworkMoveDataContainer()·SetMoveResponseDataContainer() 로 등록한다. 처리 중에는 GetCurrentNetworkMoveData() 로 읽는다.

FLAG_Custom_0..3 을 쓰려면 FSavedMove_Character::GetCompressedFlags() 를 재정의해 비트를 세우고, UCharacterMovementComponent::UpdateFromCompressedFlags() 를 재정의해 해석한다. CanCombineWith() 가 압축 플래그를 비교하므로, 커스텀 플래그가 다르면 자동으로 move 결합이 금지된다.

커스텀 MOVE_Custom 은 이동 자체의 복제도 직접 해야 한다. CharacterMovement의 예측·보정은 기본 모드(Walking/Falling 등)에 맞춰져 있으므로, 커스텀 모드의 상태를 move data에 넣고 서버에서 같은 PhysCustom 이 돌아가게 해야 한다.

7. 디버깅

  • p.NetShowCorrections 1 — 서버가 보정을 보낼 때 클라이언트/서버 캡슐을 색으로 그린다. p.NetCorrectionLifetime 으로 표시 시간을 조절한다.
  • showdebug Physics — Updated Component, 이동 모드, 발판, 속도, 루트 모션 소스를 한 화면에 본다.
  • LogNetPlayerMovement — ServerMove·ClientAdjustPosition·재생 로그. VeryVerbose 로 켜면 move 타임스탬프까지 보인다.
  • p.NetShowCorrections 는 기본 0(꺼짐)이고, 표시 시간은 p.NetCorrectionLifetime(기본 4초)이다. 서버는 서버 위치(초록)·클라 위치(빨강), 클라는 클라 위치(빨강)·보정 위치(초록)를 그린다.
  • NetEmulation.PktLag · PktLoss · PktLagVariance — 지연·손실을 넣어 예측과 보정을 재현한다. 예측 전용으로 p.NetForceClientServerMoveLossPercent·p.NetForceClientAdjustmentPercent 도 있다.
