MovementComponent — 무엇이 액터를 움직이나

무브먼트는 자기 충돌이 없다. UpdatedComponent를 움직이고, 그 컴포넌트의 충돌을 쓴다. 루트·자식·메시 중 무엇이 UpdatedComponent냐에 따라 같은 몬스터를 통과하기도 막히기도 한다.

개요 캐릭터 물리 네트워크 Root Motion 그 외

1. 무브먼트는 충돌이 아니라 "무엇을 움직일지"다

UMovementComponent 는 UActorComponent 다. 캡슐도 박스도 없고, 자기 충돌 형상을 갖지 않는다. 대신 매 틱 UpdatedComponent 하나를 골라 그 컴포넌트의 트랜스폼을 바꾼다.

UPROPERTY(BlueprintReadOnly, Transient, DuplicateTransient, Category=MovementComponent)
TObjectPtr<USceneComponent> UpdatedComponent;      // 움직일 대상

UPROPERTY(BlueprintReadOnly, Transient, DuplicateTransient, Category=MovementComponent)
TObjectPtr<UPrimitiveComponent> UpdatedPrimitive;  // 캐스팅해 둔 것

엔진 주석이 이 관계를 한 문장으로 정리한다.

스윕 이동에서는 UpdatedComponent 의 충돌만 고려한다. 붙어 있는 컴포넌트는 충돌을 무시한 채 끝 위치로 순간이동한다. — MovementComponent.h

그래서 "무브먼트의 충돌 설정" 은 곧 UpdatedComponent 의 ObjectType · 응답 · 모양이다. 액터나 자식 컴포넌트의 설정이 아니다.

UpdatedComponent 가 비어 있으면 시작할 때 액터의 루트가 자동으로 들어간다(bAutoRegisterUpdatedComponent 기본 true). ACharacter 는 여기에 더해 생성자에서 캡슐을 직접 넣는다.

// ACharacter::ACharacter
CharacterMovement->UpdatedComponent = CapsuleComponent;

2. UpdatedComponent 가 바뀌면 무엇이 바뀌나

SetUpdatedComponent() 로 다른 컴포넌트를 지정할 수 있다. 이때 달라지는 것은 세 가지다.

UpdatedComponent움직이는 것쓰는 충돌액터 루트
루트 캡슐액터 전체캡슐의 ObjectType·응답이동
자식 컴포넌트 AA 와 A 의 자식만A 의 ObjectType·응답제자리
메시 (NoCollision)메시만없음 — 스윕 안 함제자리

자식이 UpdatedComponent 면 액터는 움직이지 않는다. MoveComponent 는 그 컴포넌트의 트랜스폼만 바꾸고, 부모는 건드리지 않는다. 반대로 루트가 UpdatedComponent 면 루트가 움직이고, 자식들은 충돌 없이 따라온다.

캐릭터 메시의 기본 프로필은 NoCollision 이 아니라 CharacterMesh 다(QueryOnly, Pawn·Vehicle·Visibility Ignore). 메시를 UpdatedComponent 로 쓸 거라면 이 프로필도 같이 봐야 한다.

3. 계층 — 전부 같은 MovementComponent 가 아니다

  • UMovementComponent — 베이스. 평면 제약, 슬라이드, 관통 보정, UpdatedComponent 자동 등록.
    파생: UProjectileMovementComponent · URotatingMovementComponent · UInterpToMovementComponent
  • UNavMovementComponent — 내비게이션 에이전트 정보와 길찾기 요청(RequestDirectMove)을 얹는다.
    → UPawnMovementComponent → UCharacterMovementComponent · UFloatingPawnMovement → USpectatorPawnMovement
  • UCharacterMovementComponent — 걷기·낙하·수영·비행 모드, 계단, 바닥 판정, 네트워크 예측
  • UProjectileMovementComponent — 초기 속도·중력·바운스·호밍, 충돌 시 정지
  • URotatingMovementComponent — RotationRate 로 회전. 충돌 없이 회전한다
  • UInterpToMovementComponent — 제어점 사이를 보간 이동. bSweep 로 충돌 사용
  • UFloatingPawnMovement — 입력 가속·감속으로 이동. 스윕 사용

UPathFollowingComponent 는 무브먼트가 아니다. 길찾기는 경로를 계산해 RequestDirectMove 로 무브먼트에 "이 속도로 가라" 고 요청할 뿐, 실제 이동은 CharacterMovement 가 한다.

스윕 채널은 this->GetCollisionObjectType(), 쿼리 응답은 this 의 response container 다. 즉 움직이는 그 컴포넌트의 설정이 쓰인다.

5. 시리즈 — 더 깊이

이 페이지는 공통 뼈대다. 캐릭터의 걷기·낙하, 네트워크, 루트 모션, 나머지 무브먼트는 각각 따로 파고들었다. 처음이면 개요 → 캐릭터 물리 → 네트워크 → 루트 모션 순서가 좋다.

  • CharacterMovement — 걷기와 낙하의 물리
    PerformMovement의 순서, PhysWalking, StepUp, FindFloor, MovementBase, PhysFalling
  • CharacterMovement — 네트워크 예측과 보정
    클라이언트 예측, FSavedMove_Character, ServerMove, ClientAdjustPosition, 네트워크 스무딩
  • Root Motion — 애니메이션이 이동을 소유할 때
    RootMotionMode, FRootMotionSource, 몽타주 루트 모션, 네트워크 보정
  • Projectile · Rotating · InterpTo · Floating
    발사체의 중력·바운스·호밍, 회전·보간·부유 이동, 커스텀 무브먼트

6. 예제 — 루트 · 자식 A · 메시

앞에서 본 상황을 그대로 두자. PC 루트는 ObjectType PC, Monster 응답 Block. 자식 A는 ObjectType Col, Monster 응답 Block. 몬스터 루트는 ObjectType Monster, PC 응답 Ignore, Col 응답 Block.

UpdatedComponent채널 · 몬스터 응답결과
Root (capsule)PC · Ignore통과 · 액터 전체 이동
Child ACol · Block막힘 · 루트는 제자리
Mesh (NoCollision)—통과 · 스윕 없음

Child A 가 막히는 이유는 양쪽 응답이 모두 Block 이기 때문이다. A 가 몬스터를 Block 하고, 몬스터도 Col 을 Block 한다. 반면 Root 가 통과하는 이유는 몬스터가 PC 를 Ignore 하기 때문이다. PC 쪽이 아무리 Block 이어도 상대가 Ignore 면 min 이 Ignore 다.

루트가 움직일 때 자식 A·메시는 충돌 없이 따라온다. A 가 몬스터와 Block 관계여도, A 는 스윕의 주체가 아니라서 루트의 이동을 막지 못한다. A 가 막히는 것은 A 자신이 UpdatedComponent 일 때뿐이다.

7. 흔한 함정

증상먼저 볼 것
분명히 충돌을 설정했는데 통과한다그 설정이 UpdatedComponent 에 있는지. 자식·메시 설정은 이동에 안 쓰인다
충돌이 전혀 없다UpdatedComponent 가 UPrimitiveComponent 인지. 아니면 스윕할 형상이 없다
자식만 움직이고 액터가 안 움직인다UpdatedComponent 가 자식으로 바뀌었는지 (SetUpdatedComponent)
메시가 벽을 뚫는다메시 프로필이 CharacterMesh·NoCollision 인지. 루트 캡슐이 실제로 움직이는지
몬스터가 나를 무시한다몬스터의 내 ObjectType 응답. 내가 Block 해도 상대가 Ignore 면 통과
화면 밖에서 멈춘다bUpdateOnlyIfRendered. 안 보이면 틱을 건너뛴다
특정 액터만 무시하고 싶다UpdatedComponent 의 MoveIgnoreActors·MoveIgnoreComponents. 응답을 바꾸지 않고 스윕에서 뺀다
2D 게임인데 Z 로 날아간다bConstrainToPlane·bSnapToPlaneAtStart
멀티에서만 튄다CharacterMovement 는 예측·복제가 되지만, 직접 만든 MOVE_Custom 은 복제를 직접 해야 한다

8. 디버깅

  • showdebug Physics — 캐릭터의 CharacterMovement 상태를 띄운다. 첫 줄에 Updated Component: ... 가 나와서, 지금 무엇을 움직이는지 바로 보인다
  • show Collision — 콜리전 형상. show CollisionPawn·show CollisionVisibility 는 채널 기준
  • DisplayDebug 는 바닥·가속도·RootMotionSources·PhysicsVolume 까지 보여 준다

"왜 안 움직이지" 의 절반은 UpdatedComponent 가 엉뚱한 컴포넌트이거나 비어 있는 경우다. showdebug Physics 로 이름을 먼저 확인하는 편이 빠르다.
