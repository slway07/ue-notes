Behavior Tree ② — Composite · Decorator · Service

Selector는 "되는 것 하나", Sequence는 "전부", SimpleParallel은 "메인 + 백그라운드". Decorator는 조건과 Observer 중단, Service는 가지가 살아 있는 동안의 주기 갱신이다.

1. Composite — 자식 실행 순서

Composite규칙쓰는 곳
Selector자식을 차례로 시도, 하나 성공하면 성공"공격 가능? 추격? 배회?" 우선순위
Sequence자식을 차례로 실행, 하나라도 실패하면 실패"문 열고 → 들어가고 → 앉기"
SimpleParallel메인 Task + 백그라운드 가지"이동하는 동안 사격"

UBTCompositeNode 는 자식 목록과 GetNextChild 를 갖는다. Selector는 실패한 자식을 다음 후보로 넘기고, Sequence는 성공한 자식을 다음으로 넘긴다. 둘 다 "현재 자식"을 기억하므로 다음 틱에 이어서 평가한다.

  • OnChildActivation — 자식 가지가 활성화될 때.
  • OnChildDeactivation — 자식 가지가 비활성화될 때.
  • NotifyChildExecution — 자식 결과를 부모에 알린다.

2. Decorator — 조건과 가드

Decorator는 Composite나 Task에 붙어 "이 가지를 실행할 수 있는가"를 판단한다. 핵심 함수는 CalculateRawConditionValue 다.

Decorator하는 일
Blackboard키 값 비교(Is Set, Is Not Set, 같음, 범위 등)
Cooldown한 번 실행 후 일정 시간 동안 막는다
Loop자식을 N회 반복
TimeLimit자식이 제한 시간을 넘으면 중단
ConditionalLoop조건이 참인 동안 반복
DoesPathExist경로 존재 여부
KeepInCone시야 원뿔 안 유지

Decorator의 FlowAbortMode (에디터 표시 Observer Aborts)는 조건이 바뀌었을 때 무엇을 중단할지 정한다.

  • None — 중단하지 않는다. 조건은 다음 평가 때만 본다.
  • Self — 자기 가지만 중단.
  • LowerPriority — 아래 우선순위의 실행을 중단.
  • Both — 자기 가지 + 아래쪽 모두.

Blackboard Decorator는 키에 Observer를 등록한다. TargetActor 가 세팅되면 Observer가 깨어나 LowerPriority 가지를 중단시키고, Selector가 위쪽 추격 가지를 고르게 된다.

그림은 Selector의 위쪽 가지부터 평가하는 모습을 단순화했다. 실제로는 Decorator의 Observer가 값 변경 시점에 트리를 중단·재평가한다.

3. Service — 가지가 살아 있는 동안 주기적으로

Service는 Composite/Task에 붙어, 그 가지가 활성화된 동안 일정 간격으로 TickNode 를 실행한다. 매 틱이 아니라 Interval + RandomDeviation 주기다.

  • Interval — 실행 간격(초). 기본 0.5.
  • RandomDeviation — 간격에 더하는 랜덤 편차. 기본 0.1. 여러 AI가 동시에 도는 것을 막는다.
  • OnBecomeRelevant / OnCeaseRelevant — 가지 활성/비활성 시점.
  • TickNode 에서 Super 를 호출해야 다음 틱이 예약된다. 오버라이드에서 빼먹으면 Service가 한 번만 돈다.

대표 Service는 DefaultFocus(가장 가까운 적을 포커스)와 RunEQS(주기적으로 EQS)다. Service는 "판단"이 아니라 "상태 갱신"에 쓴다. 공격 가능 여부 같은 조건은 Decorator가 맡는다.

4. Observer 중단의 실제 순서

  1. Blackboard의 TargetActor 가 바뀐다.
  2. 그 키를 관찰하던 Decorator의 콜백이 불린다.
  3. Decorator가 FlowAbortMode 에 따라 중단을 요청한다.
  4. BT 컴포넌트가 해당 가지의 Task에 AbortTask 를 호출한다.
  5. Task는 OnTaskFinished(..., Aborted) 에서 정리한다.
  6. Selector가 다시 평가되어 새 가지를 고른다.

이때 Latent Task (MoveTo, Wait)가 중단되면 진행 중인 이동/대기가 취소된다. 그래서 "적을 발견했는데 이전 MoveTo가 계속 돈다" 같은 문제는 대개 Observer/FlowAbort 설정 누락이다.

5. SimpleParallel — 메인과 백그라운드

SimpleParallel 은 메인 Task 하나와 백그라운드 트리 하나를 동시에 돌린다. 백그라운드 종료 방식은 AbortBackground(즉시) 또는 WaitForBackground(대기)다. 예: "목표 지점으로 이동하는 동안, 백그라운드에서 주변을 스캔".

  • 메인 Task가 끝나면 전체가 끝난다.
  • 백그라운드는 메인을 끝내지 못한다.
  • 백그라운드가 실패해도 메인은 계속된다.

복잡한 병렬 행동은 SimpleParallel보다 Service + 상태 키 로 푸는 편이 디버깅하기 쉽다. SimpleParallel은 정말 독립적인 두 흐름일 때만.

BT 설계의 원칙은 Task는 행동만, 판단은 Decorator/Service로 다. Task 안에서 "적이 있으면 공격"까지 하기 시작하면 트리를 봐도 흐름을 알 수 없다.

7. 디버깅

  • BT 에디터 PIE — 현재 실행 중인 Composite/Task가 하이라이트.
  • Gameplay Debugger — ActiveNodes, Blackboard, Observer 중단을 확인.
  • Decorator의 FlowAbortMode 가 None 인지 먼저 본다. 값이 바뀌어도 트리가 안 멈추는 흔한 이유다.
