Blackboard — BT의 공유 변수판

Behavior Tree의 노드들은 자기 상태를 오래 들고 있지 않는다. Blackboard 에 목표·집 위치·상태를 적고, Decorator와 Service가 그 값을 읽는다. 값이 바뀌면 Observer 가 트리를 중단시킨다.

AI Controller Blackboard BT 구조 BT 노드 BT Task Perception EQS

1. Blackboard는 "BT 밖의 기억"

BT는 실행 중인 노드의 스택과 메모리를 갖지만, "적을 봤다", "집은 여기다" 같은 게임 상태 를 노드마다 들고 있으면 트리가 지저분해진다. 그래서 BT는 상태를 Blackboard에 두고, 노드는 키만 참조한다.

AIController
  ├── BlackboardComponent   ← 런타임 값 (TargetActor, HomeLocation ...)
  └── BehaviorTreeComponent
        ├── Decorator: TargetActor Is Set?
        ├── Service: Update Target
        └── Task: MoveTo TargetActor

Perception이 적을 발견하면 Blackboard의 TargetActor 를 쓰고, Decorator가 그 키를 보고 분기한다. **관찰자(Observer)** 는 키가 바뀌는 순간 트리에 "다시 평가해라"라고 알려 준다.

2. Asset과 Component

구분역할

UBlackboardComponent런타임 인스턴스. 컨트롤러마다 하나, 실제 값 보관

UBlackboardComponent::InitializeBlackboard(Data) 로 에셋을 연결한다. AAIController::UseBlackboard 가 이 초기화를 대신하고, RunBehaviorTree 는 BT의 BlackboardAsset 을 보고 필요한 Blackboard를 만든다.

Blackboard는 AIController에 붙는 컴포넌트 다. Pawn이나 BT 에셋에 붙는 게 아니다. 같은 Blackboard 에셋을 쓰는 BT라도 컨트롤러마다 값은 따로다.

키는 에셋에서 이름과 타입을 정한다. 같은 이름이라도 타입이 다르면 다른 키다. 키에 bInstanceSynced 를 켜면 관련 Blackboard로 값이 동기화된다. Object 키에는 Base Class 필터가 있어 "Pawn만", "Actor만"처럼 좁힐 수 있다.

4. FBlackboardKeySelector

Decorator·Service·Task는 키 이름을 문자열로 직접 받지 않고 FBlackboardKeySelector 를 쓴다. 이 구조체는 키 이름·타입·ID 를 함께 들고 있어, BT 에디터에서 키를 고르면 타입까지 맞춰진다.

  • SelectedKeyName — 키 이름.
  • SelectedKeyType — 키 타입.
  • SelectedKeyID — 런타임 키 ID.
  • ResolveSelectedKey(BlackboardAsset) — 이름으로 ID/타입을 찾는다.
  • AllowNoneAsValue(bool) — "키 없음"을 허용할지.

그래서 "TargetActor 키"를 고르면 Object 타입만 고를 수 있고, Decorator는 그 키가 Is Set 인지, Is Not Set 인지 비교한다.

6. Observer — 값이 바뀌면 트리를 깨운다

Decorator는 조건을 매 틱 계산하지 않는다. 대신 관심 있는 키에 Observer 를 등록하고, 값이 바뀔 때만 통지받는다.

FDelegateHandle Handle = Blackboard->RegisterObserver(
    KeyID, this, FOnBlackboardChangeNotification::CreateUObject(
        this, &UMyDecorator::OnBlackboardKeyChanged));

통지 콜백은 EBlackboardNotificationResult 를 돌려준다.

  • ContinueObserving — 계속 관찰.
  • RemoveObserver — 이 키를 더 보지 않는다.

Decorator의 FlowAbortMode(에디터 표시 Observer Aborts)가 Self 면 자기 가지만, LowerPriority 면 아래쪽 실행을 중단한다. Both 면 둘 다다. 이 중단이 BT에서 "적을 발견하면 순찰을 멈추고 추격" 같은 전환을 만든다. → BT Composite·Decorator

매 프레임 바뀌는 값을 Blackboard에 넣지 않는다. Observer가 계속 깨어나 BT가 매 틱 재평가된다. 위치·거리처럼 자주 변하는 값은 Service가 일정 간격으로 갱신하거나, Task가 직접 계산한다.
