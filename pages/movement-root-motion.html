Root Motion — 애니메이션이 이동을 소유할 때

애니메이션의 루트 본 이동을 코드의 속도 대신 캐릭터 이동으로 쓰는 방법. 모드 네 값, FRootMotionSource의 우선순위·누적, 몽타주의 실제 스위치, 네트워크 보정까지.

개요 캐릭터 물리 네트워크 Root Motion 그 외

1. 루트 모션이란

애니메이션에는 루트 본의 이동이 들어 있을 수 있다. 공격하며 앞으로 나아가는 몽타주, 벽을 넘는 애니메이션, 피격으로 밀려나는 동작이 그렇다. 이 이동을 애니메이션 데이터 그대로 캐릭터에 적용하는 것이 루트 모션이다.

일반 이동은 코드가 속도를 만들고 AddMovementInput 으로 밀어 준다. 루트 모션은 반대로 애니메이션이 이동량을 소유한다. 그래서 MaxWalkSpeed·MaxAcceleration 같은 속도 값이 아니라, 애니메이션의 루트 트랙이 이동 거리를 정한다.

중요한 것은 루트 모션이 충돌을 건너뛰지 않는다는 점이다. CharacterMovement는 루트 모션을 속도로 바꾼 뒤 일반 캡슐 스윕을 한다. 벽이 막으면 루트 모션도 막히고, 슬라이드한다.

2. RootMotionMode — 네 값

UAnimInstance::RootMotionMode 가 애니메이션의 루트 모션을 추출할지, 적용할지를 정한다. 기본값은 RootMotionFromMontagesOnly 다.

모드추출적용설명
NoRootMotionExtraction안 함안 함루트 이동을 애니메이션 안에 그대로 둔다
IgnoreRootMotion함안 함추출은 하지만 버린다. 이동은 코드가 담당
RootMotionFromEverything함함모든 애니메이션의 루트 모션. 네트워크 멀티플레이에 부적합
RootMotionFromMontagesOnly함함몽타주만. 네트워크에 적합. 기본

"추출"과 "적용"은 별개다. ShouldExtractRootMotion() 은 RootMotionFromEverything 과 IgnoreRootMotion 에서 true다. 즉 IgnoreRootMotion 도 루트 모션을 뽑아서 버리는 모드이지, 아예 안 뽑는 모드가 아니다.

RootMotionFromEverything 은 블렌드된 모든 애니메이션의 루트 모션을 합치기 때문에, 클라이언트와 서버의 애니메이션 상태가 조금만 달라도 이동이 어긋난다. 그래서 네트워크 게임에서는 RootMotionFromMontagesOnly 를 쓴다.

3. CharacterMovement로 들어오는 두 경로

루트 모션은 두 갈래로 CharacterMovement에 들어온다. 둘 다 결국 속도가 되어 같은 스윕을 탄다.

애니메이션 루트 모션은 RootMotionParams·HasAnimRootMotion()·AnimRootMotionVelocity 로 들어온다. 애니메이션 루트 모션은 항상 로컬이고, ConvertLocalRootMotionToWorld 로 메시 기준 월드로 바꾼다. 코드 주석도 "애니메이션 루트 모션은 속도를 덮어쓰고, 현재 다른 루트 모션 소스를 허용하지 않는다" 고 말한다.

코드 루트 모션은 ApplyRootMotionSource 로 CurrentRootMotion(FRootMotionSourceGroup)에 넣는다. 대시·넉백·점프 궤적처럼 애니메이션 없이 이동량을 만들 때 쓴다. StartTime 은 autonomous proxy면 클라이언트 타임스탬프, authority면 서버가 본 클라이언트 타임스탬프로 기본 설정된다.

4. FRootMotionSource — 우선순위와 누적

소스 하나는 Priority(높을수록 먼저), Duration(음수면 무한), AccumulateMode(Override/Additive), bInLocalSpace, FinishVelocityParams 를 갖는다. 기본값은 Duration -1, Override, 월드 공간이다.

  • Priority 20MoveToForce — 목표 지점까지 이동Override
  • Priority 10ConstantForce — 일정한 힘Additive
  • Priority 5RadialForce — 반경 안에서 밀어냄Additive

PrepareRootMotion 은 대기 중인 소스를 활성 목록에 합치고, Priority 내림차순으로 정렬한다. 그다음 소스별로 이번 틱의 이동량을 만든다.

  • Override — 가장 높은 우선순위 소스 하나만 적용하고 멈춘다. 나머지는 무시된다.
  • Additive — 여러 소스의 이동량을 합산한다.
  • 로컬 공간 — bInLocalSpace 면 UpdatedComponent 의 회전을 곱해 월드로 바꾼다.

소스가 끝나거나 제거될 때는 FinishVelocityParams 가 적용된다. 마지막 루트 모션 속도를 유지할지, 지정 속도로 바꿀지, 클램프할지를 정한다. Additive 소스가 끝나면 그 효과를 LastPreAdditiveVelocity 에서 빼서, 벽에 막혀 속도가 0이 된 뒤에도 뒤로 가지 않게 한다.

FRootMotionSourceGroup 에는 HasRootMotion() 이라는 함수가 없다. HasActiveRootMotionSources() 또는 HasRootMotionToApply() 를 쓴다. 둘은 같은 구현이다.

5. 소스 타입

  • FRootMotionSource_ConstantForce — 일정한 힘. 캐치업 시 SimulationTime / MovementTickTime 으로 힘을 키운다
  • FRootMotionSource_RadialForce — 반경 안에서 밀거나 당김. bIsPush·bNoZForce·거리/시간 감쇠
  • FRootMotionSource_MoveToForce — 시작→목표 보간. PathOffsetCurve·bRestrictSpeedToExpected
  • FRootMotionSource_MoveToDynamicForce — 목표가 움직이는 버전. SetTargetLocation·TimeMappingCurve
  • FRootMotionSource_JumpForce — 포물선 점프. Distance·Height·Rotation, 착지까지 지속 가능

MoveToForce 의 bRestrictSpeedToExpected 는 캐치업할 때 기대 속도보다 빨라지는 것을 막는다. 네트워크로 늦게 도착한 소스가 목표를 향해 과속하는 것을 방지하는 장치다.

6. 몽타주 루트 모션 — 실제 스위치는 시퀀스에 있다

몽타주에 bEnableRootMotion 같은 단일 스위치는 없다. UAnimMontage 의 bEnableRootMotionTranslation·bEnableRootMotionRotation·RootMotionRootLock 은 4.5에서 deprecated된 레거시 필드다.

실제 스위치는 UAnimSequence::bEnableRootMotion 과 RootMotionRootLock 이다. 몽타주는 슬롯 트랙이 참조하는 시퀀스의 설정을 따르고, UAnimMontage::HasRootMotion() 은 슬롯 트랙을 검사해 루트 모션이 있는지 판단한다.

  • 재생 — FAnimMontageInstance::Advance 가 OutRootMotionParams 를 만든다. SimulateAdvance 는 네트워크 재생용이다.
  • 추출 — UAnimMontage::ExtractRootMotionFromTrackRange 는 주석 그대로 첫 번째 슬롯 트랙만 본다. 여러 트랙의 루트 모션을 섞지 않는다.
  • 소비 — UAnimInstance::Montage_Advance 가 추출량을 누적하고, ConsumeExtractedRootMotion(Alpha) 가 알파만큼 소비한다.
  • 제공자 하나 — RootMotionMontageInstance 는 Montage_Play 에서 HasRootMotion() 일 때만 지정된다. 여러 몽타주가 동시에 루트 모션을 소유하지 않는다.

ERootMotionMode::RootMotionFromMontagesOnly 와 USkeletalMeshComponent::IsPlayingNetworkedRootMotionMontage() 가 함께 "지금 네트워크 루트 모션 몽타주가 도는가"를 판단한다. bRootMotionFromMontagesOnly 라는 별도 심볼은 5.8에 없다.

7. 적용 순서와 충돌

PerformMovement 안에서 루트 모션은 이동 전에 준비된다.

  1. CleanUpInvalidRootMotion — 끝난 소스를 정리하고 FinishVelocity를 적용한다.
  2. TickCharacterPose — 애니메이션 루트 모션을 소비한다.
  3. CurrentRootMotion.PrepareRootMotion — 소스별 이동량을 만든다.
  4. Apply Root Motion to Velocity — 이동량을 속도로 바꾼다. 애니메이션 루트 모션이 있으면 다른 소스는 무시된다.
  5. StartNewPhysics — PhysWalking/PhysFalling 이 그 속도로 캡슐을 스윕한다.
  6. 회전 적용 후 RootMotionParams.Clear().

PhysWalking·PhysFalling 안에서는 RestorePreAdditiveRootMotionVelocity 로 시작하고, 애니메이션 루트 모션이나 Override 소스가 있으면 CalcVelocity 를 건너뛴다. 마찰·가속으로 루트 모션을 깎지 않기 위해서다.

그다음 MoveAlongFloor 의 SafeMoveUpdatedComponent 로 실제 이동한다. 벽이 막으면 HandleImpact·SlideAlongSurface 가 돌고, 이동이 막힌 뒤 PhysWalking 이 실제 이동량으로 속도를 다시 계산한다. 그래서 루트 모션의 거리는 보장되지 않는다. 애니메이션이 3m를 요구해도 벽이 있으면 그만큼 못 간다.

상승 속도가 임계값(기본 -GetGravityZ() * dt)을 넘으면 MOVE_Falling 으로 바뀐다. 루트 모션으로 위로 솟구치면 자연스럽게 낙하로 이어진다.

8. 네트워크

루트 모션은 이동량이 애니메이션에 묶여 있어 일반 이동보다 복제가 까다롭다. CharacterMovement는 두 종류의 보정을 따로 보낸다.

  • 몽타주 루트 모션 보정 — ClientAdjustRootMotionPosition. 먼저 ClientAdjustPosition 으로 위치를 맞추고, 서버의 몽타주 트랙 위치가 다르면 FAnimMontageInstance::SetPosition 으로 점프시킨 뒤 bClientResimulateRootMotion 을 세운다. 다음 재생에서 FSavedMove_Character::PrepMoveFor 가 SimulateAdvance 로 루트 모션을 다시 만든다.
  • 소스 보정 — ClientAdjustRootMotionSourcePosition. 서버의 FRootMotionSourceGroup 을 받아 LocalID를 맞추고, 유효하지 않은 소스를 걸러낸 뒤 LastAckedMove->SavedRootMotion 과 비교한다. 다르면 SavedRootMotion 을 서버 그룹으로 바꾸고 bClientResimulateRootMotionSources 를 세운다.

응답 패킹에는 bRootMotionMontageCorrection·bRootMotionSourceCorrection 비트가 있고, 소스 그룹은 NetSerialize 로 전송한다. FRootMotionSource::NetSerialize 는 Priority·LocalID·AccumulateMode·InstanceName·CurrentTime·Duration·Status·bInLocalSpace 만 보내고, 클라이언트는 시간으로 이동량을 다시 계산한다. 5.8에는 Iris용 FRootMotionSourceGroupNetSerializer 도 있다.

bServerMoveIgnoreRootMotion 은 dual move에서 첫 move가 루트 모션이 아닐 때 서버가 루트 모션을 무시하게 하는 플래그다.
