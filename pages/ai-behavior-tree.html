Behavior Tree ① — 실행 구조

BT 에셋은 설계도, UBehaviorTreeComponent 는 실행기다. StartTree 로 시작하고, 매 틱 실행 스택을 따라 내려가며 Composite가 자식을 고르고 Task가 결과를 돌려준다.

1. 에셋과 컴포넌트

구분역할
UBehaviorTree에셋. RootNode(트리 최상위), BlackboardAsset, 그래프
UBehaviorTreeComponent런타임 실행기. 컨트롤러마다 하나
UBrainComponentBT 컴포넌트의 기반. AI의 "두뇌" 슬롯
UBehaviorTreeManagerBT 에셋 로드/캐시 관리

BT 에셋은 여러 AI가 공유한다. 각 컨트롤러는 같은 에셋을 보고 자기 InstanceStack 을 따로 만든다. 그래서 "BT 에셋을 수정하면 모든 AI가 바뀐다"가 성립한다.

2. 시작과 종료

// AIController
RunBehaviorTree(BTAsset);
  ├── UseBlackboard(BTAsset->BlackboardAsset)
  ├── BehaviorTreeComponent 생성/재사용
  ├── BrainComponent = BehaviorTreeComponent
  └── StartTree(*BTAsset, EBTExecutionMode::Looped)

RunBehaviorTree 는 BT가 요구하는 Blackboard가 없으면 UseBlackboard 로 만들고, UBehaviorTreeComponent 가 없으면 새로 만든다. 그다음 StartTree 로 실행을 시작한다.

  • EBTExecutionMode::Looped — 트리가 끝나면 처음부터 다시. 일반적인 AI.
  • EBTExecutionMode::SingleRun — 한 번만 실행하고 끝.
  • StopTree(EBTStopMode::Safe) — 진행 중인 Task를 정리하며 정지.
  • StopTree(EBTStopMode::Forced) — 즉시 정지.

UBrainComponent 쪽에는 StartLogic·StopLogic·PauseLogic·ResumeLogic·IsRunning 이 있다. BT 컴포넌트는 이 두뇌 슬롯에 들어간다.

3. 한 틱의 흐름

UBehaviorTreeComponent::TickComponent └─ ProcessExecutionRequest / ProcessExecution └─ InstanceStack[ActiveInstanceIdx] └─ ActiveNode (현재 실행 중인 노드) ├─ Composite : 다음 자식 선택 ├─ Task : ExecuteTask ├─ Decorator : 조건 / Observer └─ Service : TickNode

BT는 매 틱 트리 전체를 처음부터 다시 도는 게 아니다. 현재 활성 노드 를 유지하고, 그 아래로 내려가며 다음 자식을 고른다. Task가 InProgress 를 돌려주면 그 자리에서 멈추고, 완료 통지가 올 때까지 기다린다.

  • RequestExecution — "다시 평가해라" 요청. Blackboard 변경, Decorator Observer, Task 완료가 트리거.
  • ScheduleExecution — 다음 틱에 실행하도록 예약.
  • ProcessExecutionRequest — 예약된 요청을 실제로 처리.
  • PauseLogic/ResumeLogic — BT 전체를 일시정지/재개.

4. 노드의 네 종류

노드역할핵심 함수
Composite자식 실행 순서 제어GetNextChild, OnChildActivation
Task실제 행동ExecuteTask, TickTask, FinishLatentTask
Decorator조건/가드CalculateRawConditionValue, NotifyObserver
Service주기적 갱신TickNode, OnBecomeRelevant

Composite는 "어느 자식을 먼저 볼까"를 정하고, Task는 "무엇을 할까"를 실행한다. Decorator는 Composite/Task에 붙어 조건을 걸고, Service는 가지가 활성화된 동안 일정 간격으로 돈다. 자세한 내용은 BT Composite·Decorator·Service 와 BT Task.

5. 노드 결과

UBTTaskNode::ExecuteTask 는 EBTNodeResult 를 돌려준다.

  • Succeeded — 성공. Composite가 다음 자식으로.
  • Failed — 실패. Selector면 다음 자식, Sequence면 전체 실패.
  • InProgress — 아직 진행 중. 나중에 FinishLatentTask 로 완료를 알린다.
  • Aborted — 중단됨. OnTaskFinished(..., Aborted) 로 통지된다.

이 반환값이 BT 실행의 기본 신호다. Task가 InProgress 를 돌려주면 BT는 그 가지를 멈춰 두고, 다른 노드를 평가하지 않는다. 완료 통지가 오면 그때 다시 흐른다.

6. 인스턴싱과 노드 메모리

BT 에셋의 노드는 기본적으로 공유된다. 노드에 상태(예: 현재 순찰 인덱스)를 두려면 bCreateNodeInstance 를 켜서 인스턴스별 노드 오브젝트를 만들거나, NodeMemory 를 쓴다.

  • bCreateNodeInstance — 노드마다 인스턴스 생성. 상태를 노드 멤버에 둘 수 있다.
  • GetInstanceMemorySize — 노드별 메모리 크기. BT 컴포넌트가 인스턴스마다 할당.
  • InitializeMemory — 메모리 초기화 시점.
  • GetNodeInstance — 인스턴스 노드 얻기.

기본 Task는 상태를 NodeMemory 에 두는 패턴이 많다. 블루프린트 Task는 bCreateNodeInstance 가 켜지는 경우가 있어, C++ Task보다 인스턴스 비용이 클 수 있다.

7. Blackboard와의 연결

UBehaviorTree::BlackboardAsset 이 BT가 쓸 Blackboard를 지정한다. RunBehaviorTree 는 이 에셋으로 UseBlackboard 를 호출하고, BT 컴포넌트는 그 Blackboard를 통해 키를 읽는다.

Blackboard가 없거나 타입이 맞지 않으면 BT가 시작되지 않거나 키가 Invalid가 된다. BT 에디터에서 Blackboard를 지정하지 않으면 노드의 키 선택이 비어 보이는 이유다.

8. 디버깅

  • BT 에디터를 PIE 중에 열기 — 실행 중 노드가 하이라이트된다.
  • Gameplay Debugger (') — Behavior Tree 카테고리에서 ActiveNode와 Blackboard를 본다.
  • showdebug AI — 컨트롤러의 경로/포커스 상태. BT/Blackboard는 Gameplay Debugger에서 본다.
  • stat AIBehaviorTree — BT Tick/Search/Execution 비용.
